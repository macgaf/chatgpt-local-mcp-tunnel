# 附加目录访问

`root` 继续作为默认工作目录。需要访问主 root 外的系统临时目录、用户临时目录或外部数据目录时，在本机配置中增加 `additional_roots`。默认值是空列表，已有单根配置无需修改。此修订的源码与用户当前安装分开验证；未包含该字段的旧版程序不会提供此功能。

## 配置

以下是合并到已有 `config.json` 的字段片段，保留已有 root、模式、文件规则、Tunnel 和凭据设置：

```json
{
  "additional_roots": [
    {"path": "/tmp", "mode": "read_only"},
    {"path": "${TEMP_DIR}", "mode": "read_only"}
  ]
}
```

该示例适用于 macOS 上两个临时目录不同的情况。Linux 的 `${TEMP_DIR}` 可能就是 `/tmp`，此时只添加一次；同一真实目录重复配置会拒绝启动。Windows 可使用 `${TEMP_DIR}` 或 `${TEMP}`，不使用 `/tmp` 示例。确需访问 `/var/tmp` 时再单独添加，并确认该目录存在。

每项只接受 `path`、`mode`。`mode` 省略时为 `read_only`；明确需要写入且全局 `mode=read_write` 时，可将相应条目改为 `read_write`。需要专属可写目录时，在本机创建它，再授权该子目录，无需开放整个共享临时目录。

`path` 支持绝对路径、`~/` 以及以下占位符，后面可追加子目录：

| 占位符 | 启动时的含义 |
|---|---|
| `${TEMP_DIR}` | Python `tempfile.gettempdir()` 返回的当前进程临时目录，适用于三平台 |
| `${TMPDIR}` | 当前进程的 `TMPDIR` 环境变量，macOS 常用 |
| `${TEMP}` | 当前进程的 `TEMP` 环境变量，Windows 常用 |
| `${TMP}` | 当前进程的 `TMP` 环境变量 |

除 `${TEMP_DIR}` 外，未设置的变量会明确报错，不回退到其他路径。环境来自实际启动 MCP 的进程；终端与登录后服务可能不同。路径在启动时解析，后续环境变量变化不自动改变授权。目录必须存在，拒绝相对路径、父目录跳转、HOME 上级目录、未知字段及非法模式。

## 权限和路径语义

- 全局 `mode=read_only` 禁止所有写入，即使某个附加目录配置了 `read_write`。命令与 Git 推送仍需各自开关授权。
- `write_roots` 继续只限制主 root 内的路径；它不授予主 root 外的访问权限。附加目录的写入由自身模式限制。
- `allow`、`deny`、`force_allow` 按各授权根内的相对路径匹配。重叠根的文件规则同时校验；更窄的授权不能绕过父范围的拒绝规则，主 root 的 `write_roots` 也继续生效。
- 重叠根以最具体的根决定目录模式，因此可以只读授权一个临时目录，再单独读写授权其中的专属子目录。所有授权根本身都不能作为修改目标。
- 实际用户级凭据存储位置、服务配置／程序／私有状态、硬链接、普通文件限制、SHA 前置校验、锁、备份和写后校验继续执行；项目中的同名目录或文件不会因名称被推测为秘密，详见 [文件访问规则](FILE_ACCESS_POLICY.md)。配置根的原始路径和真实路径均检查保护规则；授权根自身的中间祖先也执行逐级防链接检查。MCP 授权仍受操作系统当前用户的访问权限限制。
- 同目录的大小写和 Unicode 规范等价写法通过文件系统身份核实，不能绕过更窄的只读范围；真正不同的大小写敏感目录保持独立。同一目录的不同写法也不能重复注册。
- 相对路径仍基于主 root。工具对主 root 内的文件继续返回相对路径，外部文件返回绝对路径，可直接用于后续读取或修改。
- 配置 `/tmp` 或 `${TMPDIR}` 时会保存启动时的真实目录边界。配置中存在的根目录别名可以使用；别名改指其他目录会报 `ROOT_ALIAS_CHANGED`。目录内部的符号链接仍检查词法路径与真实目标，写入继续拒绝内部链接路径。
- 搜索和 Git 向上查找以本次所属授权根为界；一次调用不会自动扫描其他附加目录。备份绑定具体文件及其所属授权根，移除目录授权后不能借备份绕过权限。

## 生效和验证

在本机备份配置并合并已授权条目，再重启自己管理的 MCP/Tunnel 实例。远程 MCP 不提供修改权限或重启自身的工具。

1. 调用 `policy_info`，检查 `additional_roots` 中的规范化 `path`、配置 `mode` 和全局模式约束后的 `effective_mode`。
2. 使用其中的真实绝对路径调用 `list_directory`，再读取已授权的普通文件。
3. 如需验证写入，仅在已授权的可写子目录中创建合成测试文件并读回 SHA；验证只读目录和授权范围外路径明确拒绝。

`diagnose(path=...)` 返回 `authorized_root` 和写策略诊断；该诊断本身不证明磁盘写入成功。`${TEMP_DIR}` 只代表当前进程选择的一个临时目录，并不授权所有系统／其他用户的临时目录。完整测试和未覆盖的平台、部署范围见 [测试报告](../TEST_REPORT.md)。
