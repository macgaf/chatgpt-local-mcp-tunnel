# 非文本文件的自动化链路

## 已实现：先让模型直接看到内容

本机路径 → 策略检查 → 有界读取 → 对应适配器 → MCP 的 content[]。

- `read_image` 返回 `type=image`、mimeType、data；不是把 Base64 包进普通文本 JSON。允许 EXIF 纠正、按原图方向坐标裁剪/缩放；元数据解释坐标映射。
- `render_pdf_page` 本机 PDFium 渲染单页，返回 ImageContent。`read_document` 文字提取不代表图表已读，扫描件没有执行 OCR。
- `list_archive`/`read_archive_member` 直接读取 ZIP 中的图像、PDF、文本和原始二进制。拒绝危险路径、凭据、链接、重复名称和高压缩比；不落地解压。
- `read_binary` 返回 EmbeddedResource；URI 带 offset/length/sha256，可通过 `resources/read` 拉取后续块。ZIP 资源使用独立 archive URI，避免与普通文件路径混淆。每块均有 hash，整文件版本变化时拒绝继续。
- `visual_probe` 在内存生成随机字符图片，文本仅有答案哈希。用户/模型必须看图片，不能通过文本答案假通过。

对于建模照片、图表、ZIP 中的参考图，这条路线不需要“手工上传到聊天”。但实际宿主必须把图像块交给具备视觉的模型；这是部署验收项，而不是服务端可自行保证的事。

## 客户端需要文件字节时

兼容客户端可循环读取资源：保存每块到自己授权的临时目录，核对 chunk_sha256，再按 offset 拼接并核对整体 sha256。完成后，由该客户端把真实文件接入自己的沙箱/附件 API。

本项目没有冒充 ChatGPT 附件上传接口；`local-mcp://...` 不等于 `sandbox:/mnt/data/...`。ChatGPT 的宿主若不支持资源落盘，服务端不能凭一个字符串生成该宿主的文件。此时优先本地适配器生成可直接消费的图片/文本，而不是让用户重复上传。

## 下一阶段专用适配器方案（尚未实现）

| 文件 | 本地自动处理 | 给模型的结果 |
|---|---|---|
| `.blend` | 固定 Blender 可执行文件 + 禁用文件 auto-exec + 受信渲染脚本 | 指定视角截图、对象/相机/几何元数据 |
| 视频 | 固定解码器，按时间范围/帧预算抽帧 | 带时间戳的 ImageContent；音频按明确授权的本地转写器处理 |
| LAS/PLY/GLB | 格式专用只读解析器/渲染器 | 点云/网格概览、统计量、所选视角 |
| DOCX/XLSX/PPTX | 有界文档解析器 | 段落/单元格/页片段；图形部分渲染为图片 |

适配器不能变成任意 `run_command`：可执行程序/脚本仅在本机配置白名单，输入只读，输出隔离，禁用宏/嵌入脚本，限制时间、内存、文件大小和网络；失败报告具体格式、依赖、退出码。共享同一策略与错误系统。原始文件不改写。

对实际尺寸测量/摄影测量，应使用原图数据或明确标定的裁剪坐标；缩略图视觉判断不等于重新运行 SfM/BA、读取 EXIF 就具有厘米级精度，也不等于已经解析 Blender 内部几何。
