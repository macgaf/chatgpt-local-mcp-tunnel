# 提示词驱动安装与验收

## 电脑工具版入口与版本范围

自动准备任务使用 [完整电脑版提示词](prompts/setup-with-computer.txt)，与 README 第 3.1 节同步。普通界面由已授权电脑工具操作，检查和保存由本机执行器完成；系统要求本人批准的步骤只暂停该项，批准后复测并继续。工具可用、页面打开、权限实际选中、本机保存、Read/Use 认证和 ChatGPT 连接须分别验证。

稳定安装来自 main。`tunnel prepare` 的候选实现位于 `fix/browser-tunnel-preparation` / PR #2，尚未合并且未完成真实网站创建验收。执行前核对实际代码及 --help；需要候选执行器时先检查已有副本，保留原工作区修改，不另造重复链路或声称主线已有该命令。

该提示词要求一次连接内完成探针、准备、保存与验证，普通界面优先 Computer Use，仅安全转存需要时使用 DevTools。现有候选执行器仍校验 Restricted Read + Use，All／永不过期及跨阶段单连接支持尚待实现和验收；文档更新不代表功能发布。

项目内容变更按 AGENTS.md 的 GitHub 同步约定提交、推送并读回确认；不能只生成提示词附件。这与本机安装、权限修改及草稿 PR 合并是不同操作。

完整安装提示词见 [README 第 3.2 节](../README.md#install)，自动准备网站资源见 [第 3.1 节](../README.md#platform)及[自动准备细则](AUTOMATED_TUNNEL_SETUP.md)。这里区分本机自动保存和人工备用方式，不要求用户把已有凭据再输入一遍。

## 源码来源与已有安装升级

安装与升级统一使用 `main`；`feat/local-mcp-v0.3` 保留为开发历史，不再作为安装入口。优先复用现有仓库，核对 origin、HEAD、工作区及本地分叉。仅在没有本地修改、未完成合并且可以安全快进时更新；不擅自 stash、reset、clean 或删除分支。

源码更新后重新运行完整安装器，再让用户重启自己管理的旧实例；不能把 git pull 当成升级已部署程序。记录源码 SHA，因为版本仍是 `0.4.0`。保留已确认的目录、权限、凭据来源、日志和其他 MCP 条目。README [第 3.7 节](../README.md#upgrade) 提供升级提示词。

## 目录和权限由用户选择

默认候选 `~/`（等同 `~/.`），也可以指定更具体的现有目录。用户选择 `read_only` 或 `read_write`；已有明确选择不重复问。读写时确认 write_roots，HOME 全范围可写需明确确认。网站资源准备不等于授权本机文件读写。

确认后检查 Python 3.11+、Git、Codex CLI，以相同的非敏感 root/mode 参数先运行 `bootstrap.py --plan`，再用对应平台的完整安装入口执行。缺系统依赖时说明并征求安装授权，不自行 sudo。全程不因为准备凭据而开启 MCP Shell 或 Git 推送。

## 先消费已有缓存，再处理缺失

第 3.1 节授权本机 Codex 实际查找/创建资源并自动安全保存：本机程序可以处理 ID/key，模型和工具消息不接收实际值。该流程依赖实际授权的电脑／浏览器通道及已验证的本机执行器。优先检查 PR #2 中已有的阶段实现；主线尚未包含候选命令，不以文档更新代替程序和实机验收。

安装阶段先检查已核验的本机 Tunnel 配置和该 Tunnel 对应 keystore 条目。已存在且适合目标的凭据直接复用，**不要再让用户执行 tunnel configure/key set**。只有状态文件、没有运行器可用绑定时，由同一本机辅助脚本核验并导入；不能把缓存文件存在当成安装器自动接入成功。

尚未安装时的准备状态只存本项目专用、受保护配置目录，key 正文仍只入系统凭据库。安装接续只更新必要绑定，保留 root/mode/write_roots、文件规则和无关配置。失败不覆盖旧凭据，不让网站新建在每次重试时重复执行。

`key status` 证明本地可读，不证明远端有效或符合所选权限与有效期。库锁定先解锁，403 查权限/关联，DNS/TLS/超时查网络；这些情况不作为创建新 key 的理由。网页只有旧 key 掩码而本机无完整值时不能恢复原 key，确认缺失后才按用户授权新建专用普通项目 Runtime key（All 权限、Never／永不过期），并保留旧 key。

## 隐藏输入只作为备用

已确认不能建立安全自动转存通道、用户选择人工方式后，在独立本机终端使用：

```text
local-mcp tunnel configure
local-mcp key status
local-mcp key set
```

前者隐藏输入 ID，已有正确值可保留；后者隐藏输入 key 并进入系统凭据库。实际值不能通过模型的 write_stdin、工具参数、echo 或源码传递。没有 TTY 或隐藏输入失败时停止人工入口，不改用回显输入。**非交互本机脚本直接操作 keystore 是另一条授权路径，不等同于绕过隐藏输入 CLI 的检查。**

ID 必须保存在本机受保护配置/profile；key 不写入 config.json。不能承诺底层工具、系统审计或浏览器完全无痕。Linux 无桌面继续使用 [systemd 凭据路线](LINUX_CREDENTIALS.md)，不擅自切换来源。

## 网站操作不是只导航

有明确用户授权时，普通创建字段、选择 All 和 Never／永不过期、提交和保存应实际执行，不逐步交回用户。最终敏感阶段由本机程序连续完成，不把完整 DOM、网络响应或屏幕截图送到对话。创建前先验证凭据库存取，保存读回成功后才关闭一次性密钥弹窗。原生界面操作工具若必然泄漏这些值，先检查其可用的本地安全接口，不能靠“最终回复不显示”来掩盖工具日志暴露。

只在登录、验证码、系统授权、管理员审批、真正的目标歧义或安全转存能力缺失时暂停相关步骤。不得绕过浏览器/助手权限限制、复制 Cookie 或创建额外管理权限。

## 验证与继续执行

运行 `self-test`；ID/key 可用后运行 `tunnel init` 和 `doctor --with-tunnel`。未安装时可以报告资源已保存、安装尚未执行；不能把本机启动失败误写成凭据无效，也不能把权限检查和认证检查混为一项。未执行的探针标记未验证。

`tunnel run` 是持续运行命令，由独立终端运行，或经用户另行授权管理为服务。本轮资源准备不自动开机自启。Codex stdio 本地连接不依赖 Tunnel，ChatGPT 是否连接另行验收。

| 层级 | 通过条件 |
|---|---|
| 云端资源 | 目标组织/工作区明确，Tunnel 真实存在并关联 |
| 本地保存 | 运行器可读取对应 keystore，读回一致；不是只有网页条目或掩码 |
| 权限与认证 | All 权限、永不过期及所属上下文已核对，真实 Tunnel 认证探针有成功结果 |
| 安装 | 实际启动器和版本可运行 |
| 本机 MCP | stdio 握手、工具发现与读取成功 |
| Codex | list/get 注册正确，新会话实际调用 policy_info |
| ChatGPT | 已选中 App 后实际调用工具 |
| 图片／写入 | 对应视觉测试通过；只有授权后新建测试文件并读回校验 |

## 日志与报告

安装器会打印日志目录；用实际启动器执行 `logs path`、`logs show --component install`、`logs show --level ERROR`。源码和脚本尚未运行的错误不一定有持久日志。辅助程序只输出阶段、布尔状态、错误类别，不把 ID/key、原始浏览器响应或变量写入日志。日志导出前仍审核，详见 [日志说明](LOGGING.md)。

最后报告实际新建/复用状态、本机保存与认证结果、版本、配置/启动器/日志路径及剩余阻碍。自动保存成功不要求用户确认“已手工保存”；本次文档修订本身不算网站操作已成功。
